当前实现里确实存在大量重复计算，不是简单“每个特征 FFT 7 次”，而是更重：

  - 现在是“每个样本 × 每个频带”都跑一遍 build_context。
  - build_context 每次包含：多次滤波 + 2 次 STFT（标准窗和短窗）+ ridge 动态规划    + iSTFT + 小波包。
  - 7 个频带意味着每个样本大约 14 次 STFT（还不含其他重步骤），不是只 FFT 7 次。

  你看到“1-2 分钟后才更新进度条”，是因为当前进度条按 future 完成更新；单个 future  太重，前几个任务没完成前不会动。

  ———

  方案A：程序设计优化（CPU，保持公式不变）

  目标：不改特征公式、不减特征数量，只重构计算图，减少重复。

  1. 单样本一次性频谱缓存（核心）

  - 对每个样本先做一次预处理（去均值 + 1k~100k 带通）。
  - 计算并缓存：
      - 全频 rfft / irfft 频谱
      - 标准窗 STFT（一次）
      - 短窗 STFT（一次）
  - 之后 7 个频带通过“频域掩膜”从缓存中切片得到 band 结果，而不是重跑 STFT。

  2. 上下文分层

  - GlobalContext（样本级，只算一次）：预处理信号、两套 STFT、小波包所需基础量。
  - BandContext（频带级，轻量派生）：用掩膜得到 band 功率、band ridge、band residual，再喂给现有特征公式。
  - 这样公式保持不变，只是输入来源从“重复重算”改为“缓存派生”。

  3. 任务并行改成“样本级并行”

  - 不再“同一样本内 7 频带并发”，改为“不同样本并行”。
  - 每个 worker 连续处理一个样本的 7 频带，复用该样本缓存，cache 命中最大。

  4. 进度条改成两级

  - 一级：文件夹样本进度（每完成 1 个样本就更新，不卡 1-2 分钟）。
  - 二级：可选 band 子进度（调试模式开）。

  5. 线程改进

  - 设定 OMP_NUM_THREADS=1, MKL_NUM_THREADS=1（避免 BLAS 与 Python 线程过度嵌套导致 30% 假空闲）。
  - Python 层用 ProcessPoolExecutor（重 CPU 更稳），而不是单纯增线程数。

  ———

  方案B：GPU 优化（保持公式不变）

  目标：把大矩阵/频谱计算搬到 GPU，公式不变，最后与 CPU 做一致性校验。

  1. GPU 负责的部分

  - 预处理滤波（可用 cupyx.scipy.signal）
  - FFT / STFT（cupy.fft 或 torch.stft）
  - 频带掩膜、功率谱、谱质心、谱熵等张量运算

  2. CPU 保留的部分（先不硬搬）

  - 少量复杂控制流：ridge 动态规划、部分 SciPy 统计函数、小波包（pywt）
  - 做法：GPU 算完关键谱量后按需回传 CPU，避免全流程重写风险。

  3. 批处理策略

  - 按 mini-batch 样本上 GPU，减少 kernel 启动/拷贝开销。
  - 所有 7 个频带掩膜一次性并行应用（[bands, freq, time] 张量），一趟得到多频带谱特征基础量。

  4. 可靠性保障（必须做）

  - CPU/GPU 双跑抽检：同一样本同频带同特征，误差阈值如 rtol=1e-5, atol=1e-7。
  - 只有全部通过再切默认 GPU 路径；否则自动回退 CPU。
