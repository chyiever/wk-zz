## 3. 开发过程问题与解决方案

### 问题1：notebook 中中文变成 `?`

现象：

- markdown 与 code 注释中的中文在 notebook 中被替换为 `?`，例如：
  - `axes[-1].set_xlabel("?? (s)")`
  - `fig.suptitle("??????????")`

原因分析：

- 终端/脚本执行链路存在编码不一致，导致写入 `.ipynb` 时中文字符被替换为问号。
- 这不是 notebook 渲染问题，而是源文件已被污染。

解决方案：

1. 对两个 notebook 执行字符级清理，删除所有 `?`。
2. 重置 code cell 运行输出，避免历史错误堆积。
3. 建议后续 notebook 内容编辑优先在 VSCode/Jupyter 内直接编辑并保存为 UTF-8，避免通过受限终端注入中文大段文本。

当前状态：

- 已确认两个目标 notebook 内 `?` 计数为 0。

### 问题2：`ModuleNotFoundError: No module named 'src'`

现象：

- notebook 运行导入时报错：
  - `from src.das_localization...`
  - `ModuleNotFoundError: No module named 'src'`

原因分析：

- Jupyter 的工作目录可能在 `notebooks/`，而非项目根目录，导致 `src` 不在 `sys.path`。

解决方案：

- 在 notebook 首个代码单元增加项目根目录探测与 `sys.path` 注入逻辑：
  - 优先检测当前目录是否含 `src`
  - 否则尝试父目录
  - 将项目根目录插入 `sys.path`

当前状态：

- 已加入路径兼容逻辑，可在常见启动方式下导入成功。

### 问题3：批处理窗口参数与短数据长度不匹配

现象：

- 批处理时 `win_size=256`，而样例帧长约 192，导致窗口数为 0。

原因分析：

- 原始滑窗逻辑未处理 `n <= win_size` 的短序列情况。

解决方案：

- 更新 `batch.py`：当总长度小于窗口长度时，回退为“整段作为一个窗口”。

当前状态：

- 批处理不再返回空结果。

### 问题4：样例数据定位结果被拒识

现象：

- 在默认阈值参数下，单样本结果常为 `rejected`。

原因分析：

- 数据长度短、有效时延点偏少，且 PSR/时延窗阈值偏严，导致可用通道不足。

解决方案：

- 建议在 notebook 参数区进行调参：
  - 下调 `PSR_TH`
  - 放宽 `MAX_TAU_SEC`
  - 适当下调 `N_VALID_MIN`
  - 对比 `best_snr` 与 `fixed` 参考通道

当前状态：

- 代码逻辑正常，拒识是质量门控策略生效，不属于程序错误。

### 问题5：`4.1` 与 `5.1` 筛选口径不一致，导致“筛选后点数反而更多”

现象：

- 在 `notebook1` 的 5.2 图中，筛选后（`valid`）红点数量多于 4.2（`quality_mask`）的峰值点。
- 实际统计日志（2026-05-19）：
  - `Total channels: 28`
  - `4.1 quality_mask selected: 14`
  - `5.1 valid selected: 28`
  - `Only in 5.1 (valid & ~quality_mask): 14 [0,1,2,3,4,5,6,7,8,23,24,25,26,27]`

原因分析：

- `4.1` 的 `quality_mask` 判据更严格，包含：
  - `raw_snr_proxy >= snr_th`
  - `peak_val_all >= peak_th`
  - `delay_res.psr >= PSR_TH`
  - `physical_mask`
- `5.1` 的 `valid` 判据是另一套口径（并非在 `4.1` 基础上二次筛选）：
  - `delay_res.valid_mask & physical_mask`
- 在该样本上，`delay_res.valid_mask` 与 `physical_mask` 基本全 True，所以出现 `valid=28/28`。

解决方案：

1. 修复 5.2 代码单元变量兼容问题：
   - 原报错：`NameError: name 'lag_sec' is not defined`
   - 现改为优先使用 `lag_t`，否则回退 `lag_sec`，再回退 `lag_idx/FS` 重建时延轴。
2. 在 notebook 新增“4.1 vs 5.1 掩码关系对比”单元，打印数量、交集、差集并落盘：
   - `outputs/das_localization/intermediate/nb1_mask_comparison_41_vs_51.csv`
3. 将 5.2 code 注释改为 ASCII，规避部分终端链路中文注释显示为 `?` 的问题。

当前状态：

- 现有 notebook 中，`5.1` 与 `4.1` 仍是“并行两套标准”，不是严格“逐级加严”关系。
- 若业务要求“5.1 必须在 4.1 基础上进一步筛选”，建议将 `valid` 改为：
  - `valid = quality_mask & delay_res.valid_mask & physical_mask`
  - 并保留 `valid[ref_idx] = True`。
