# 2026-5-18 CV 单类折问题原因分析、影响及其解决方案

## 1. 问题背景

在 `notebooks/2026-05-17_cross_condition_experiment.ipynb` 第 3 节（多模型跨条件评估）重跑过程中，日志多次出现如下告警/报错：

- `FitFailedWarning`
- `ValueError: This solver needs samples of at least 2 classes ... only one class`

该问题发生在交叉验证相关流程中，典型出现在 `LogisticRegression` 的拟合阶段。

## 2. 根因分析

### 2.1 数据行顺序存在标签分块

当前样本存在明显顺序特征：前半段集中为一类，后半段集中为另一类。  
在这种情况下，任何“按顺序取前 N% 子样本”的流程都可能拿到单类数据。

### 2.2 第 3 节中学习曲线子采样受顺序影响

第 3 节训练诊断使用 `learning_curve(train_sizes=[0.25, 0.5, ...])`。  
若不显式打乱，子样本抽取会受到原始行顺序影响，小训练规模时更容易抽到单类。

### 2.3 “整体类别平衡”不等于“每个折/子样本都双类”

即使单元格统计显示总体正负样本数量接近，交叉验证折、学习曲线子样本、不同实验子集（不同 train domains）仍可能局部失衡，导致单类折。

## 3. 影响评估

### 3.1 交叉验证稳定性下降

单类折会导致部分拟合失败，出现 `FitFailedWarning`，并使对应分数无效或变成 `nan`。

### 3.2 模型比较与参数选择可信度下降

CV 失败折会污染训练诊断与模型比较，影响对模型优劣的判断。

### 3.3 阈值与误差结构可能被放大

当前流程在 OOF 概率上选阈值；当训练评估不稳定时，阈值可能更容易向极端值偏移，进一步放大“低 FP、高 FN”的结果形态。

## 4. 本次修复方案（已实施）

修复位置：`notebooks/2026-05-17_cross_condition_experiment.ipynb` 第 3.1 代码单元。

### 4.1 在每个实验训练集构建后先打乱行顺序（可复现）

已新增：

```python
train_df = train_df.sample(frac=1.0, random_state=random_state).reset_index(drop=True)
```

目的：消除标签分块顺序对后续子采样和诊断流程的影响。

### 4.2 learning_curve 显式启用随机子采样

已新增：

```python
shuffle=True,
random_state=random_state,
```

目的：避免学习曲线在小 `train_size` 下按顺序取样导致单类子样本。

## 5. 同期修复补充（第 3 节汇总口径）

在同一轮修复中，还处理了第 3 节统计口径问题：

- 修复模型间测试结果累积污染；
- `n_test_domains` 从错误的“行数”改为“测试域去重计数”；
- 修复后 `n_test_domains` 应稳定为 3（对应 `F130/F130A/F130C`）。

## 6. 验证建议

重跑第 3 节后建议重点核查：

1. `FitFailedWarning` 和 `only one class` 是否显著减少或消失。  
2. `all_experiments_model_summary.csv` 中 `n_test_domains` 是否全部为 3。  
3. 训练诊断曲线是否仍出现大量 `nan` 或异常波动。  

## 7. 后续优化建议

1. 在 CV 层面引入更严格的分组切分策略（按源样本/母文件分组）以进一步降低信息穿透与局部单类风险。  
2. 对阈值策略做并行对照（目标召回阈值、最大平衡准确率阈值、固定阈值）以提升结论稳健性。  
3. 在第 3 节增加折级类别计数审计输出，形成常态化质量门禁。
