# 2026-4-19 特征计算函数迁移使用指南

## 1. 迁移目标

本指南说明如何把 `src/fea_cpt` 迁移到其他项目中使用，并保持输入、输出、参数和结果解释的一致性。

## 2. 最小迁移清单

至少复制以下文件：

- `src/fea_cpt/__init__.py`
- `src/fea_cpt/base.py`
- `src/fea_cpt/io_utils.py`
- `src/fea_cpt/logging_utils.py`
- `src/fea_cpt/signal_ops.py`
- `src/fea_cpt/features.py`
- `src/fea_cpt/importance.py`
- `src/fea_cpt/pipeline.py`
- `src/fea_cpt/params.py`

依赖包：

- `numpy`
- `pandas`
- `scipy`
- `scikit-learn`
- `pywavelets`
- `joblib`
- `tqdm`
- `matplotlib`（仅 notebook/绘图需要）
- `nbformat`（仅 notebook 生成需要）

## 3. 输入数据要求

默认读取 `npz` 文件，最关键字段为：

- `phase_data`：一维信号数组
- `sample_rate`：采样率
- `type`：样本类型

可选字段：

- `starttime`
- `arrival_time`
- `timestamp`

如果新项目的数据格式不同，只需要修改 `load_feature_record`，保证输出 `FeatureRecord` 即可；上层特征接口无需改动。

## 4. 在新项目中的调用方式

### 4.1 单样本调用

```python
from pathlib import Path
from fea_cpt.io_utils import load_feature_record
from fea_cpt.params import DEFAULT_FEATURE_PARAMS
from fea_cpt.signal_ops import build_context
from fea_cpt.features import compute_all_features

record = load_feature_record(Path('your_sample.npz'))
context = build_context(record, DEFAULT_FEATURE_PARAMS)
result = compute_all_features(context)
print(result.features)
```

### 4.2 批量调用

```python
from fea_cpt.params import build_feature_params
from fea_cpt.pipeline import compute_feature_table_for_paths

params = build_feature_params(highpass_hz=1000.0, n_jobs=1)
feature_table = compute_feature_table_for_paths(sample_paths, params=params, show_progress=True)
```

### 4.3 保存完整数据集

```python
from fea_cpt.pipeline import build_feature_dataset

frame = build_feature_dataset('data', output_dir='outputs/fea_cpt_export')
```

## 5. 可调参数建议

优先调整以下参数：

- `highpass_hz`
  适用场景：基线漂移明显、低频干扰严重。
- `main_band_hz`
  适用场景：不同传感器或采样系统的有效频带不同。
- `stft_window_ms` / `short_stft_window_ms`
  适用场景：事件更短或更长，需要重新平衡时间分辨率与频率分辨率。
- `ridge_main_search_hz` / `ridge_h2_search_hz`
  适用场景：已知主频和二倍频主要落在新的频带范围内。
- `wavelet_level`
  适用场景：采样率更高或事件更长，希望分得更细。
- `damped_freqs_hz` / `damped_decay_ms`
  适用场景：目标瞬态阻尼频率或衰减时长与当前默认设定不同。

参数详细注释已集中放在 `src/fea_cpt/params.py`。

## 6. 输出解释

特征表固定包含 5 个样本标识字段：

- `sample_id`
- `sample_name`
- `sample_type`
- `sample_type_code`
- `path`

其余列均为特征向量元素。建议同时保存：

- `feature_table.csv`
- `feature_vector_mapping.csv`

这样在后续训练、筛选、画图和复现实验时可以稳定追踪“第几个特征对应哪个名字”。

## 7. 特征重要性排序迁移方式

若目标任务有标签，可直接使用：

```python
from fea_cpt.importance import rank_feature_importance

meta_cols = ['sample_id', 'sample_name', 'sample_type', 'sample_type_code', 'path']
feature_cols = [c for c in feature_table.columns if c not in meta_cols]
importance_tables = rank_feature_importance(
    feature_table[feature_cols].fillna(0.0),
    feature_table['sample_type_code'],
    task='classification',
    top_k=20,
)
```

当前内置三种方法：

- 互信息 `mutual_info`
- 随机森林 `random_forest`
- 置换重要性 `permutation`

## 8. 迁移时的注意事项

- 如果采样率较低，必须同步下调 `main_band_hz`、`ridge_h2_search_hz`、`harmonic_band_hz` 的上限。
- 如果事件很短，STFT 窗长和小波层数不能照搬当前默认值。
- 如果输入不是 `npz`，优先改 `io_utils.py`，不要直接改特征函数。
- 如果希望引入更高精度的矩阵铅笔或稀疏字典实现，应优先替换 `features.py` 中相关局部函数，保持外部接口不变。
- 当前默认 `n_jobs=1` 是为了兼容受限环境；在普通本地环境中可以适当调大。

## 9. 推荐迁移流程

1. 先复制 `src/fea_cpt` 全部源码。
2. 修改 `load_feature_record` 适配新数据格式。
3. 用 1 个真实样本调用 `compute_all_features` 检查是否能完整跑通。
4. 用少量多类别样本调用 `compute_feature_table_for_paths` 检查特征表分布。
5. 调整 `params.py` 中的频带、窗长和阻尼搜索网格。
6. 最后再接入建模、重要性排序或在线部署流程。
