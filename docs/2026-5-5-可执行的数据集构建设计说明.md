# 2026-5-5 可执行的数据集构建设计说明

## 1. 目标

本说明用于定稿 `BK14` 断丝样本与 `F130 / F130A / F130C` 流噪声样本的数据集构建方案，作为后续开发 `src/dataset_build` 模块与 `notebooks/dataset_build.ipynb` 的唯一实现依据。

本次构建目标如下：

- 构建原始断丝训练/测试子集：`BK14_tr`、`BK14_te`
- 构建原始流噪声训练/测试子集：`F130_tr`、`F130_te`、`F130A_tr`、`F130A_te`、`F130C_tr`、`F130C_te`

- 生成完整的数据集构建日志 `dataset_build_log.csv`
- 生成完整的数据集构建说明 `dataset_build.md`

本说明只定义构建规则、目录结构、日志字段与模块边界，不包含具体代码实现。

## 3. 总体设计原则

### 3.1 原则一：先划分，再增强

所有训练集/测试集划分必须先在原始样本层面完成，再进行混合增强，禁止先增强再划分，防止训练集与测试集发生样本泄漏。

### 3.2 原则二：统一目标采样率

所有输出样本统一为 `500kHz`，以保证：

- 后续特征提取参数统一
- 样本长度统一
- Notebook 中无需按采样率分支处理

### 3.3 原则三：混合样本长度统一

所有混合断丝样本输出时长固定为 `0.02s`，与流噪声样本长度一致。

### 3.4 原则四：保持可追溯

每个输出样本都必须能够从文件名、`data_info`、`dataset_build_log.csv` 三个层面追溯到：

- 使用了哪两个原始样本
- 使用了什么参数
- 通过哪次构建流程生成

### 3.5 原则五：固定随机种子

所有涉及随机性的步骤必须支持固定随机种子，确保构建结果可复现。

### 3.6 原则六：避免测试集泄漏

流噪声样本划分不能使用完全逐文件随机打散的最简方案，应优先按“近邻时间段”分组后再划分，减少相邻切片同时进入训练集与测试集的风险。

## 5. 原始数据划分规则

### 5.1 `BK14` 划分规则

`BK14` 共 24 个样本，按断丝生成方式分层划分：

- `BK14_tr`
  - `cut` 8 个
  - `corrosion` 8 个
  - 合计 16 个
- `BK14_te`
  - `cut` 4 个
  - `corrosion` 4 个
  - 合计 8 个

要求：

- 分层随机划分
- 固定随机种子
- 输出划分清单到日志

### 5.2 `F130 / F130A / F130C` 划分规则

原方案中的 `7:3` 比例保留，但实现口径调整为：

- 先对样本按来源时间顺序排序
- 再按“近邻时间段”进行分组
- 以组为单位做 `7:3` 划分

默认分组建议：

- 先按采样率分组：`200kHz`、`500kHz`
- 再按文件名中的时间戳排序
- 按连续固定块大小进行分组

默认块大小建议：

- `F130`：每组 10 个样本
- `F130A`：每组 20 个样本
- `F130C`：每组 10 个样本

补充规则：

- 若最后一组样本数不足，保留为单独一组
- 先打乱组顺序，再按 `7:3` 划分组
- 不允许同一组同时进入训练集和测试集


这样做的目的：

- 降低相邻切片跨集合分布带来的泄漏风险
- 尽量保持训练集/测试集在采样率与时间分布上的基本一致性

### 5.3 划分结果数量规则

每个流噪声数据集的训练/测试数量允许因分组策略带来轻微偏差，不强制要求精确等于 `70% / 30%`，但应满足：

- 训练集占比在 `65% ~ 75%`
- 测试集占比在 `25% ~ 35%`

最终数量以实际分组结果为准，并在日志与文档中记录。

## 6. 混合断丝数据集构建规则

### 6.1 输出数量规则

对每个流噪声域分别构建混合断丝数据集，样本数量与对应流噪声子集完全一致：

- `len(BK14_f130_tr) == len(F130_tr)`
- `len(BK14_f130_te) == len(F130_te)`
- `len(BK14_f130a_tr) == len(F130A_tr)`
- `len(BK14_f130a_te) == len(F130A_te)`
- `len(BK14_f130c_tr) == len(F130C_tr)`
- `len(BK14_f130c_te) == len(F130C_te)`

### 6.2 单个混合样本构建流程

以构建 `BK14_f130_tr` 中某个样本为例：

1. 从 `F130_tr` 中随机抽取 1 个流噪声样本 `signal1`
2. 从 `BK14_tr` 中随机抽取 1 个断丝样本 `signal2`
3. 将 `signal1` 和 `signal2` 都统一到 `500kHz`
4. 依据 `signal2` 的 `arrival_time` 截取一个 `0.02s` 的断丝窗口 `signal3`
5. 计算混合信号 `signal4`
6. 将 `signal4` 以 `npz` 形式保存到 `BK14_f130_tr`
7. 将生成信息写入 `dataset_build_log.csv`

### 6.3 `signal3` 的断丝截窗规则

已知：

- `signal2` 原始时长约 `0.06s`
- `arrival_time` 可从头文件获取
- 输出窗口长度固定为 `0.02s`

截窗规则：

- 令 `arrival_offset_s = arrival_time - starttime`
- 令 `t ~ U{-0.0080, -0.0079, ..., 0.0049, 0.0050}`
- 窗口起点为 `arrival_offset_s + t`
- 窗口长度为 `0.02s`

采样要求：

- `t` 必须为 `0.0001s` 的整数倍
- 若按该起点截窗越界，则重新采样新的 `t`
- 最多重试固定次数
- 若超过最大重试次数仍失败，则该条样本构建报错并写日志

说明：

现有 `BK14` 数据的 `arrival_offset_s` 约在 `0.012s ~ 0.0193s`，在 `t ∈ [-0.008, 0.005]` 条件下，原则上可以安全截取 `0.02s` 窗口，但代码中仍必须做边界检查。

### 6.4 混合公式

原方案保留线性混合形式：

```text
signal4 = w1 * signal1 + w2 * signal3
```

其中：

- `signal1`：流噪声样本
- `signal3`：断丝截窗样本
- `w1`、`w2`：随机权重

### 6.5 权重规则

原方案中 `w1`、`w2` 在 `[0.5, 1.5]` 间随机。该规则保留，但增加以下约束：

- `w1`、`w2` 从 `[0.50, 0.51, ..., 1.49, 1.50]` 中离散采样
- 小数点后保留两位
- 两者允许相等，也允许不相等

同时新增一个质量控制步骤：

- 计算混合前后 RMS
- 计算断丝分量与噪声分量的 RMS 比
- 写入日志（混合前两信号各自的RMS、RMS比、混合后的RMS比）

说明：

本阶段不引入“目标 SNR 反推权重”的更复杂策略，先按用户原方案落地；若后续发现样本能量分布过散，再在第二版中升级为 SNR 控制模式。

补充说明：

- 5kHz 高通滤波仅用于质量控制阶段的 RMS 指标计算
- 实际生成 `signal4 = w1 * signal1 + w2 * signal3` 时，使用去均值、统一采样率后的原始信号，不对混合输入额外滤波

### 6.6 预处理规则

在混合前执行以下标准化步骤：

1. 转为 `float64`
2. 去均值
3. 统一采样率到 `500kHz`
4. 保证 `signal1` 与 `signal3` 长度一致

本阶段不做：

- 归一化到固定峰值
- 能量归一化
- 用于实际样本生成的额外滤波

原因：

- 先尽量保留原始信号幅值关系
- 仅通过 `w1`、`w2` 调整混合比例

### 6.7 输出样本标签规则

混合样本统一作为“断丝类”样本处理，并在元数据中保留：

- 断丝方法：`cut` 或 `corrosion`
- 噪声来源：`F130` / `F130A` / `F130C`

### 7.4 输出文件名规则

原方案中的“随机一位小写字母”改为更稳妥的短尾缀，防止重名。

建议文件名格式：

```text
{signal2_stem}-mix-{noise_dataset}-{w1}_{w2}_{t}-{suffix}.npz
```

示例：

```text
BK14-FIP-500K-20260323T120121.475-mix-f130-0.83_1.12_-0.0017-a7.npz
```

规则：

- `suffix` 为两位随机小写字母或字母数字组合
- `t` 使用秒值，保留 4 位小数
- 避免使用会影响路径或解析的特殊字符
- `{signal2_stem}`中的采样率统一调整为500K

### 11.0 程序总览

`src/dataset_build` 当前按“入口 - 处理 - 输出 - 记录”四层拆分，核心调用链为：

1. `notebooks/dataset_build.ipynb` 只负责设置参数并调用入口函数
2. `pipeline.py` 负责串联加载、划分、重采样、截窗、混合、写文件、写日志
3. `loaders.py`、`splitters.py`、`resample.py`、`windowing.py`、`mixers.py`、`writers.py` 负责各自的单一职责
4. `logging_utils.py`、`manifests.py`、`stats.py` 负责日志、清单和统计输出
5. `__init__.py` 只暴露外部调用所需的入口和数据类，不承载业务逻辑

这样拆分的目的，是让构建流程可以被 Notebook、脚本或后续自动化任务复用，同时保证每个模块只负责一类稳定职责。

### 11.7 `mixers.py`

### 11.8 `writers.py`

### 11.9 `logging_utils.py`

### 11.10 `manifests.py`

### 11.11 `stats.py`

## 12. Notebook 边界定稿

`notebooks/dataset_build.ipynb` 只负责调度，不承载核心业务逻辑。

Notebook 应负责：

- 设置输入路径
- 设置输出路径
- 设置随机种子
- 设置划分比例
- 设置目标采样率
- 设置 `w1`、`w2`、`t` 范围
- 选择是否构建 `F130 / F130A / F130C`
- 展示数据集样本数统计
- 展示划分结果摘要
- 展示构建进度条
- 可视化抽样波形与混合结果
- 调用 `pipeline.py` 完成构建

Notebook 不应负责：

- 直接写复杂业务逻辑
- 直接实现重采样
- 直接实现混合算法
- 直接拼接日志
